# 設計書：期間の月指定・任意期間＋戦略インサイト拡充（2026-09-06）

ユーザー承認済み（インサイトは「数字の深掘り＋示唆まで」、施策提案はしない）。

## 1. 期間指定の拡張

### Period の種類
`kind: 'last12' | 'last24' | 'year' | 'all' | 'month' | 'custom'`

| 指定 | URL | start/end | label |
|---|---|---|---|
| 月 | `period=YYYY-MM` | 月初〜月末 | `2026年8月` |
| 任意期間 | `period=custom&from=YYYY-MM-DD&to=YYYY-MM-DD` | from〜to（from≤to・実在日付） | `2026-04-01〜2026-06-30` |
| 年 | `period=YYYY`（既存） | | 選択肢は **2017年〜今年** を自動生成 |

不正値（形式違反・from>to・存在しない日付）は既定（直近12ヶ月）にフォールバック。

### 比較期間（priorPeriod）と表示ラベル
- `month` → -12ヶ月（前年同月）… ラベル「前年同月比」
- `custom` → 期間日数 ≤ 366 なら -12ヶ月（「前年同期間比」）、> 366 なら期間日数ぶん過去へシフト（「前期間比」）
- `last24` → -24ヶ月（「前24ヶ月比」・既存）／その他 → -12ヶ月（「前年比」）
- `comparisonLabel(p)` を period.ts に追加し、KPIカードのサブラベルに使う。

### パラメータの直列化
`periodQuery(p): Record<string,string>`（`period` と、custom のとき `from`/`to`）を period.ts に置き、**期間セレクタ・月/期間フォーム・粒度トグル・ヒートマップのコースフォーム・サイドバーリンク**のすべてがこれを使う（各所での `kind==='year' ? … : kind` 直書きを撤廃）。

### トレンドの粒度
- `Granularity = 'month' | 'week' | 'day'`。`day` はバケット=日付、ラベル `M/D`。
- `defaultGranularity(p)`: 期間日数 ≤ 92 → `day`、それ以外 `month`。
- `allowedGranularities(p)`: 期間日数 ≤ 92 → `['day','week','month']`、それ以外 `['month','week']`。
- `g` パラメータが許容外/未指定なら既定にフォールバック。トグルは許容粒度のみ表示（`g` を常に明示）。
- 前年重ね（priorYearSeries）は月次のみ（既存どおり）。

### UI
- 既存セレクタ（直近12/24・全期間・年）の下に `<details>` 「月・期間を指定」。中に (a) `<input type="month" name="period">`＋「表示」 (b) `period=custom` hidden＋`<input type="date" name="from">`〜`<input type="date" name="to">`＋「表示」。両フォームは `view`/`course` を hidden で引き継ぐ（`g` は引き継がない＝新期間の既定粒度に任せる）。
- 現在が month/custom のとき: details は open、入力欄に現在値を入れ、セレクタ先頭に現在期間のラベルを selected で表示（custom の場合は select フォームにも from/to hidden を含める）。

## 2. 戦略インサイトの拡充

### 出力構造
`buildInsights(input): InsightGroup[]`、`InsightGroup = { title: string; items: { text: string; hint?: string }[] }`。
入力: `{ all, period, kpi, heatmap, trend, courseRows, sourceRows }`。内部で `priorPeriod` の KPI／コース別／流入経路／ヒートマップを再計算して比較する。**比較対象データが無い項目は行ごと省略**（ウソの比較を出さない）。`hint` は「→ こう読める」の1文まで（施策提案なし）。

### グループと内容（数値はすべて期間内・前期間は priorPeriod）
1. **売上の要因**: 売上と前期比（額と%）。前期に件数があるとき要因分解 `件数要因 = (件数 − 前期件数) × 前期客単価`、`単価要因 = (客単価 − 前期客単価) × 件数` を「内訳: 件数増減で±X円・客単価変化で±Y円」。hint: |件数要因| ≥ |単価要因| → 「→ 変化は主に客数（件数）によるもの」、そうでなければ「→ 変化は主に客単価によるもの」。
2. **勢い**（月次バケットが3以上のときのみ）: 前年同月に3件以上ある月の中で前年同月比が最大／最小の月（「最も伸びた月: 2026年5月（+40%）／最も落ちた月: …」）。直近3バケット合計 vs 前年同月合計（「直近3ヶ月（6〜8月）は前年同期比 +8%」）。hint: 直近3ヶ月の比率 ≥ 期間全体の前期比 → 「→ 足元の勢いは期間平均より強い」／それ以外「→ 足元は期間平均より鈍い」。
3. **曜日・季節**: 土日比率（前期比つき）。最多曜日（既存ロジック）。月次バケット3以上ならピーク月と件数シェア。hint: 土日比率 ≥ 60% → 「→ 週末への依存度が高い」／それ以外「→ 平日にも一定の需要がある」。
4. **コース**: 最多コース（件数シェア・売上シェア）。前期に3件以上あるコースの中で前期比が最大／最小のコース。hint: 最多コースの売上シェアが件数シェア＋10pt以上 → 「→ 主力コースは単価も高く収益の柱」／件数シェア ≥ 60% → 「→ 特定コースへの集中度が高い」／それ以外は hint なし。
5. **リピート**: リピート率（前期・pt差）。新規件数・リピート件数の前期比。hint: 新規が減りリピートが増 → 「→ リピーターが支え、新規獲得が課題」／新規が増 → 「→ 新規獲得が伸びている」／それ以外「→ 大きな変化なし」。
6. **流入経路（自己申告）**: 最多経路とシェア。Instagram経由シェア（前期比）。未回答・不明の合計シェア。hint: 未回答・不明 ≥ 30% → 「→ 未回答が多く、予約時の「経緯」の把握精度が分析の伸びしろ」／Instagramシェアが前期より上 → 「→ Instagram経由が伸びている」／それ以外 hint なし。

### 表示
戦略インサイトカード内で、グループごとに小見出し（13px・太字）＋箇条書き。hint は同じ行の末尾に muted で表示。
